# ADR 0006 — Contratti applicativi, JobManager e porte d'infrastruttura

- **Status:** Accepted (design)
- **Context:** CLI e futura UI Windows devono usare le stesse operazioni mentre la costruzione dell'indice avviene senza bloccare l'interfaccia.
- **Decision:** use cases `InitializeApplication`, `SelectDirectory`, `Request/RunSynchronization`, `SearchDocuments`, `GetIndexStatus`, `GetJobStatus`, `GetDocument`; porte `FileDiscoveryPort`, `DocumentReaderPort`, `SnapshotRepositoryPort`, `SettingsRepositoryPort`. `IndexingJobManager` separato da `IndexSynchronizer`, un job attivo alla volta, progress indipendente dalla UI, supporto esecuzione sync/async dello stesso algoritmo.
- **Alternatives considered:** accoppiare comandi UI direttamente a reader/index, metodi duplicati per CLI/UI, progress grafico dentro il core.
- **Consequences:** testabilità e portabilità, DTO espliciti, più file di struttura ma responsabilità nette.
- **v1 clarification (2026-11-06):** in-process, worker sync e query fuori thread UI, lock storage e attesa alla chiusura in [ADR 0009](0009-desktop-runtime.md). Contratti estesi con ClearLocalData, JobRef.reused e paginazione; nessun trasporto remoto.
- **Related:** [Interface Contracts](../INTERFACE_CONTRACTS.md), [UX Windows](../UX_WINDOWS.md).
- **M3 clarification (2026-11-06, approvata):** `BuildIndex` espone il build completo sincrono iniziale, con `BuildResult` (conteggi, byte, durata), e `SearchDocuments` usa i DTO esistenti. CLI `local-document-search DIRECTORY`, radice relativa/assoluta validata nell'infrastruttura, prefissi approvati e tutti i risultati tramite pagine da 50; EOF/Ctrl+C chiudono la sessione. Codici 0/1/2/130 definiti nei contratti. Una directory e un repository volatile per sessione; nessun JobManager, settings operativo o diff anticipato. La scelta consente invocazioni riproducibili e test di processo senza aggiungere dipendenze. [Evidenze M3](../M3_VERIFICATION.md).

- **M6 clarification (2026-11-06):** backend persistente separato dalla CLI Homework, come concordato. InitializeApplication, SelectDirectory e GetIndexStatus condividono ApplicationState; RunSynchronization è bloccante e restituisce SyncResult. Nessun JobRef anticipato. Worker/async/lock restano M7. [Superficie M6](../INTERFACE_CONTRACTS.md#8-superficie-operativa-m6).

- **M7 implementation clarification (2026-11-06, approvata):** InitializeApplication e SelectDirectory restituiscono ApplicationState con JobRef senza attendere il job; RequestSynchronization restituisce lo stesso ID con reused=true durante il lavoro. RunSynchronization attende quel medesimo job. SearchDocuments/GetDocument mantengono execute e aggiungono submit con Future, su un worker letture separato. Stati immutabili conservati per la sessione; nessun Qt o nuova dipendenza. [Contratti M7](../INTERFACE_CONTRACTS.md#9-superficie-operativa-m7), [evidenze](../M7_VERIFICATION.md).

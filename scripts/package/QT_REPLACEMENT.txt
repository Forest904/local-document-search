Sostituzione delle librerie Qt nel pacchetto Windows

L'applicazione usa DLL Qt e plugin QML separati. Per provare una variante
compatibile, chiudere Local Document Search, copiare la directory installata
in un percorso di prova, sostituire nella copia la DLL o il plugin con una
build compatibile Qt 6.12.0 per Windows x64, conservando nome e ABI, e avviare
la copia. Non modificare l'installazione originale durante la prova. Per
ripristinare, ricopiare i file originali dal medesimo installer completo.

Per Qt PDF usare una build compatibile Qt PDF 6.140.0 per Qt 6.12.0;
il sorgente Qt PDF/PDFium corrispondente e incluso nell'archivio qtwebengine
elencato in SOURCES.json. La prova storica V2-07 non copre Qt PDF.

Gli archivi sorgente upstream Qt e PySide6 si trovano in sources/; provenienza
e SHA-256 sono in licenses/upstream/SOURCES.json. I componenti Qt distribuiti
sono elencati in BUILD-MANIFEST.json, payload_components.qt.files. Conservare
avvisi e licenze dei componenti quando si distribuiscono build sostitutive.

Prova V2-07 con una DLL realmente ricostruita: verificare l'hash dell'archivio
qtbase-everywhere-src-6.12.0.tar.xz in BUILD-MANIFEST.json; estrarlo in un
percorso breve senza spazi. In un prompt MSVC 2022 x64 configurare QtBase
con CMake e Ninja in Release, build condivisa, test ed esempi disattivati;
compilare il target Qt6Core.dll. Copiare l'installazione in una nuova
directory di prova, sostituire solo qt6core.dll nella copia e avviare l'EXE.
La DLL ricostruita deve avere hash diverso dall'originale. Il rapporto
docs/V2_07_INSTALLER.md nel repository registra comandi, hash e ricerca
sintetica TXT/MD/PDF eseguita con questa procedura.
